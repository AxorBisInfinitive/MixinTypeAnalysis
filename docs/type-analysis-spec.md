# 类型分析规范

草案版本为 0.1，编写日期为 2026-11-25。

本文整理 MixinTA 的类型分析与表示迁移模型，用于约束后续设计、实现和测试。文中的“应”表示本草案要求满足的契约，“可”表示允许选择的实现方式，“待定”表示仍需确定的设计。当前实现状态在文末单独列出，其余涉及前向传播、引用类型迁移和规则求解的内容属于设计草案。

**TA 根据迁移声明和规则，建立值、调用与存储之间的关系，求解完整的改写计划。**

`(II)I -> (DD)I` 和 `(J)V -> (Lexample/BlockPos;)V` 均可表达为方法参数表示的迁移。数值 primitive 之间可采用 Java 显式 cast。long 与 BlockPos 之间的业务关系由迁移声明及规则提供。

本草案以位置数据为贯穿案例。`example/BlockPos` 表示示例类，具体编码、可变性和空值契约由实际项目确定。

```java
long pos = blockPos.asLong();
queue.add(pos);
long next = queue.poll();
BlockState state = lookup(next);
```

选定整条数据链迁移后，目标代码形态可以为下例。

```java
BlockPos pos = blockPos;
queue.add(pos);
BlockPos next = queue.poll();
BlockState state = lookup(next);
```

该结果依赖产生值、容器、调用边界和行为规则共同成立。queue 的创建、其他访问以及 lookup 的声明也应纳入分析。后续示例中的 Java 代码描述目标行为，实际改写对象为 class 字节码。

**一个分析批次对应固定输入快照及明确的覆盖边界。**

批次应记录以下输入。

| 输入 | 内容 |
| --- | --- |
| ClassLoader 上下文 | 类定义和方法解析使用的上下文 |
| Mixin 前快照 | 原目标声明、原方法体和待准备的 Mixin |
| Mixin 后快照 | 实际参与分析的类、方法、字段和调用指令 |
| 迁移声明 | 目标位置、旧表示、新表示及传播策略 |
| 改写规则和摘要 | 适用条件、数据关系、输出动作及规则身份 |
| 覆盖边界 | 可改写类、可读取外部元数据、外部调用及允许的转换 |

实际处理顺序为声明准备、Mixin、TA 求解与改写、JVM 定义类。声明准备需要先于 Mixin 对相关 Mixin 方法的预处理。TA 使用 Mixin 后快照建立传播关系，覆盖由普通 Mixin 新增或改变的调用点。

可读取的外部 class 元数据和可改写输入应分别记录。读取到一个方法的描述符，能够用于解析类型和调用目标。分析该方法如何存储、传递或观察数据，还需要其方法体或适用摘要。

覆盖保证以登记集合、可解析调用关系和已声明的外部契约为边界。相关调用经过反射、生成代码、未知动态派发或其他 ClassLoader 时，应记录对应的覆盖条件。缺少相关信息的路径在报告中保留为待解决边界。

**方法、值和共享存储应采用各自的迁移范围。**

| 对象 | 必须处理的范围 | 可采用的处理方式 |
| --- | --- | --- |
| 方法描述符 | 指向旧方法的相关调用与引用 | 改写调用、声明的适配或转发方案 |
| 一个值 | 该值的各个使用位置 | 传播新表示，在选定使用处转换表示 |
| 字段 | 相关读、写、初始化和观察 | 统一迁移字段及访问，或在访问边界适配 |
| 数组或容器元素 | 相关别名及元素操作 | 统一满足存储契约，必要时迁移存储实现 |
| 共享方法 | 各调用上下文及其实现 | 复用摘要、调用点适配或受支持的实现特化 |

必须处理的范围由签名、数据流和共享关系推导。允许继续传播的范围由声明控制。传播边界应具有可执行的处理方案，所有受影响调用与访问均应在最终计划中获得处理结果。

例如 lookup 的描述符变更会影响其所有相关调用。作者可选择让部分调用的数据链继续采用 long，并在边界使用已声明的转换方法。若选择保留旧描述符的转发方法，该方法的生成、访问权限、转换行为和签名冲突也应列入计划。

**迁移身份、JVM 类型和值之间的对应关系应分别保存。**

迁移身份标识一次声明所提出的表示变化。默认可由目标类、方法、完整原描述符、参数或返回值位置及新表示生成。显式命名可用于关联多个声明，具体注解形式待定。

同为 `long -> BlockPos` 的两个声明可能处理不同的数据。关联它们需要兼容性依据。一次迁移所涉及的具体值，由来源、使用关系和规则逐步确定。

对应关系描述旧值与新值如何关联。以选定的编码规则为例，可记录下列关系。

```text
旧值 v = encode(p)
新值 v' = p
对应关系 R(v, v') 满足 v = encode(v')
```

编码、从既有 long 构造对象、比较新对象和保留对象快照，可以分别需要不同规则。每个方向的可用性、有效输入和行为契约均应单独成立。

业务关系由规则作者声明。TA 应检查匹配、绑定、类型、访问、数据流、控制流及输出结构是否满足这些声明。替换方法允许改变的算法行为，以迁移声明为准。迁移过程还应保留声明要求保留的周围行为。

**分析应以值的定义和使用为基础，并保留跨控制流的来源集合。**

每个分析值应能关联其产生指令、使用位置、JVM 类型、迁移要求、来源集合及推导依据。局部变量槽和调试信息用于定位及展示。分析值的身份应能区分槽复用和不同定义。

在控制流合流处，应合并所有可能到达的来源，并对最终选择的新表示施加兼容性要求。正常边和相关异常边都应参与分析。循环和递归应通过可终止的摘要与约束求解处理。

```java
long pos;
if (condition) {
    pos = blockPos.asLong();
} else {
    pos = cachedPosition;
}
lookup(pos);
```

lookup 的新参数要求会同时约束两条来源。第一条来源可由 receiver 规则解决，第二条来源继续追踪 cachedPosition 或采用已声明的边界转换。所有到达最终使用位置的路径均有合法处理方案后，该要求才算满足。

同一个值可以在不同使用位置采用不同表示。

```java
BlockPos pos = blockPos;
queue.add(pos);
writeLegacyFormat(encode(pos));
```

计划应记录每条使用关系上的转换。产生值的表达式可能有副作用，复用或拆分表示时应保留规定的求值顺序和次数。

**前向事实传播与反向需求传播共同求解迁移。**

反向需求从新签名等迁移起点追踪到来源。

```text
lookup 参数需要 BlockPos
  <- next
  <- queue.poll 返回值
  <- queue 元素
  <- 所有相关写入值
  <- asLong 返回值
```

产生值规则和可用摘要提供前向事实。

```text
asLong 结果可由 receiver 提供新表示
  -> pos 可提供 BlockPos
  -> queue 写入可提供 BlockPos
  -> poll 可提供 BlockPos
  -> next 可满足 lookup 参数要求
```

某个值暂时缺少对应关系时，应保存待求解约束。其他路径、方法摘要或候选方案可能继续提供信息。求解达到稳定状态后，仍未满足的要求才进入最终诊断。

“尚未得到事实”“实现能力不足”“事实相互冲突”应具有可区分的状态。例如一个未分类的 long 属于待求解信息，已经确认的时间戳写入与位置迁移则需要兼容规则、边界处理或冲突诊断。

**改写规则应声明匹配、绑定、条件、产出和依赖。**

| 规则内容 | 契约 |
| --- | --- |
| 身份和版本 | 支持诊断、重复检测和缓存失效 |
| 适用迁移 | 指定规则服务于哪些表示关系 |
| 匹配 | 定位调用、字段、操作或其他受支持结构 |
| 输入绑定 | 指定 receiver、参数、旧结果和来源值的使用方式 |
| 前置条件 | 声明类型、可达来源、存储关系和行为要求 |
| 产生的事实 | 声明新表示、数据关系和适用摘要 |
| 输出动作 | 指定辅助调用、指令替换或其他受支持生成动作 |
| 依赖与边界 | 声明辅助方法、外部契约及新增覆盖要求 |

匹配以方法符号和分析后的值关系为基础。方法调用应包含 owner、名称、完整描述符及必要的调用种类。规则对继承解析和动态派发的适用范围应明确。

下面描述 receiver 规则的含义，具体注解名称和参数形式待定。

```text
匹配 example/BlockPos.asLong()J
适用于选定的位置迁移
输入绑定为原调用的 receiver
新结果由该 receiver 提供
规定原调用的空值、异常、副作用和快照处理
```

带注解的 Java 方法可提供运行时辅助实现。规则注册时应检查其描述符、参数绑定、可见性及运行时可达性。分析器通过方法体和元数据进行分析，辅助方法中的业务逻辑在生成代码的运行阶段执行。

一条规则可提出进一步分析需求，例如追踪某个返回值，或检查某个容器的全部相关写入。该规则的方案应保留这些依赖，直到依赖满足。

多个规则修改相同结构时，应检查它们的动作是否兼容。涉及同一方法实现、新签名或共享存储的候选动作，也应进行整体冲突检查。

**数据流摘要描述值的关系和行为效果，可独立于替换实现提供。**

摘要可包含参数到返回值的传递、字段或元素的读写、参数保留、对象逃逸、别名、回调、比较、排序和相关异常行为。规则库可以为外部方法提供摘要，普通方法体也可自动推导摘要。

例如下列方法可得到返回值来自参数 0 的关系。

```java
static long identity(long value) {
    return value;
}
```

该关系可服务于多个调用上下文。位置调用和时间戳调用可以具有不同迁移要求。摘要求解得到的可行关系，应继续接受字节码生成能力检查。

若生成过程需要增加 BlockPos 版本，应对新描述符、调用分配、访问权限、递归关系及冲突进行验证。涉及方法覆盖或接口派发时，相关派发契约也属于必须处理的范围。

摘要应记录其适用的实现和输入条件。对同一动态调用存在多个可能目标时，全部相关目标均需要适用摘要或可分析实现。无法确定的相关目标应形成覆盖边界。

**共享容器应同时满足元素传播契约和操作行为契约。**

容器分析应将别名关联到抽象存储位置。可用对象创建位置及受支持的调用上下文区分存储，具体精度策略待定。字段、数组、视图和迭代器之间的共享关系也应由实际分析或摘要提供。

基本元素摘要可描述下列关系。

```text
add 的参数 0 是 receiver 元素存储的一个可能写入值
poll 返回值来自 receiver 元素存储
poll 同时具有其声明规定的空容器行为和存储变化
```

每个读取结果应考虑所有可能来源及操作契约。写入与读取的值对应关系应由具体容器行为证明，元素类型摘要用于汇总可能值。

分析应覆盖所有相关写入、读取、比较、删除、排序、回调及保留操作。容器传入外部方法后，该方法的存储和访问行为由实现或摘要提供。精度不足时应报告无法区分的关系，并允许后续通过更精确分析或声明补足。

对于普通泛型 queue，调用描述符可以继续采用下列形式。

```text
add  (Ljava/lang/Object;)Z
poll ()Ljava/lang/Object;
```

调用方原来的 long 传递通常包括 Long 装箱和拆箱。迁移后，分析器需要根据已选方案调整对应指令。

| 操作 | 旧表示 | 新表示 |
| --- | --- | --- |
| 写入元素 | long，经 Long.valueOf 提供 Object | BlockPos，经引用传递提供 Object |
| 读取元素 | Object，经 CHECKCAST Long 和 longValue 得到 long | Object，经 CHECKCAST BlockPos 得到引用 |
| 局部变量访问 | long 对应的加载和存储 | 引用对应的加载和存储 |
| lookup 调用 | 参数描述符为 J | 参数描述符为 Lexample/BlockPos; |

泛型 Signature 等元数据的处理，应与可执行指令的类型关系一致。分析所需的逻辑元素表示应在擦除类型为 Object 时继续保存。

专门存储 long 的容器可能需要替换构造、实现类、字段、数组和相关方法。容器迁移规则应明确这些动作及其行为关系。某个使用点需要新元素类型时，相关共享存储的其他访问也应获得一致处理方案。

**规则应明确表示迁移会影响的可观察行为。**

| 行为 | 需要声明或推导的信息 |
| --- | --- |
| receiver 求值 | 次数、顺序、空值及相关异常 |
| 对象可变性 | 编码值快照和保留引用之间的对应关系 |
| 空容器读取 | null、primitive 默认值及拆箱异常的映射 |
| 相等和排序 | 数值比较、对象比较及 comparator 的关系 |
| 算术和位操作 | 新表示下对应的操作或边界转换 |
| 默认初始化 | 字段和数组的零值、null、哨兵值含义 |
| 其他消费者 | 日志、序列化、回调和外部调用采用的表示 |
| 共享访问 | 相关别名、同步和其他已声明存储效果 |

例如 `a.asLong() == b.asLong()` 需要数值相等对应的处理规则。选择对象引用比较或调用对象方法时，应有满足所需行为的依据。

从 Queue<Long> 读取空队列后赋给 long，会经过 null 拆箱。新表示允许 null 时，是否保留原来的失败位置与异常，属于需要选择的行为。字段或数组从 long 迁移为引用时，默认初始化也应获得对应处理。

这些契约可以由内建语义、适用摘要、业务规则和迁移声明共同提供。报告应展示行为选择及其依据，便于审查作者授权的变化。

**候选方案应隔离其条件和失败原因。**

对于同一要求，求解器可以同时发现改写来源、调用点转换、方法特化或其他可用方案。每个候选方案应记录其前置条件、动作、依赖、覆盖要求及失败原因。

候选方案的条件尚未满足时，可保持待求解状态。一个候选方案失败后，其他合法方案继续参与求解。最终失败应指向全部允许方案均无法解决的要求，或无法消除的方案歧义。

候选方案各自提出的假设应保持可区分。最终计划只提交相容方案所支持的事实和动作，多个备选方案中的条件变化需要分别追踪。

传播策略可规定优先传播范围、允许的转换边界、可采用的生成动作及明确的规则选择关系。具体策略形式待定。稳定排序用于展示结果，具有语义差异的方案选择应具有声明依据。

数据流求解与候选选择应分别建模。工作队列处理受事实变化影响的依赖节点，候选选择处理可行方案之间的兼容关系。循环及递归可使用摘要和相依关系分组求解。

分析抽象和上下文策略应保证一个批次内的求解可终止。达到实现的精度或搜索能力边界时，报告能力边界及残留要求。该结果应与已经证明的语义冲突区分。

**分析流程应先完成约束与方案求解，再生成字节码。**

1. 固定输入快照、覆盖边界、迁移声明、规则及策略。
2. 检查声明结构，准备 Mixin，并取得真实 Mixin 后快照。
3. 从迁移起点建立相关值、调用、存储和控制流关系。
4. 提取或读取摘要，传播前向事实及反向需求。
5. 生成候选方案，继续求解其依赖和共享约束。
6. 依据策略选择整体相容的方案，检查覆盖完整性。
7. 汇总未解决要求、歧义、能力边界和确定冲突。
8. 生成可审查的整批改写计划。
9. 在独立输出快照中执行计划，计算并验证输出。
10. 验证全部成功后发布批次产物，由运行时提供给类定义过程。

独立可分析部分的诊断应继续收集。输入结构错误使某部分无法继续分析时，应记录依赖该错误的受阻范围，其他可分析部分继续处理。

图构建可从受影响位置向相关调用和存储闭包扩展。缓存应包含实际输入快照、规则版本、迁移上下文和策略。Mixin 输出、摘要或边界条件变化时，相关缓存依赖也应更新。

同一批次的推导应持续增加已确认事实或缩小可行方案范围。最终动作在求解结束后提交。按规则逐轮修改原字节码产生的临时结果应与固定分析输入分别管理。

**每条关键结论应保留来源，诊断应按根因组织。**

诊断模型应能够提供下列信息，具体数据结构和错误码待定。

| 信息 | 用途 |
| --- | --- |
| 类型和阶段 | 区分缺少声明、歧义、冲突、覆盖和实现能力 |
| 迁移身份 | 指明哪个目标要求触发分析 |
| ClassLoader 和符号位置 | 定位类、方法、完整描述符、字段或参数 |
| 指令和可选源码位置 | 定位产生值、使用位置和存储访问 |
| 需求与已知事实 | 展示期望表示、来源集合及当前结论 |
| 传播路径 | 解释该位置与迁移目标的关系 |
| 候选方案及原因 | 展示已考虑的处理方式和前置条件 |
| 根因与受影响位置 | 合并派生失败，同时保留影响范围 |
| 可补充信息 | 指出规则、摘要、实现或边界中缺少的关系 |

格式示意如下。

```text
迁移目标
  lookup 参数 0 需要 BlockPos

尚未解决
  queue 的一处写入来自 loadCachedPosition 返回值
  该返回值缺少位置表示关系

传播路径
  loadCachedPosition 返回值
  -> queue 写入
  -> queue.poll 返回值
  -> lookup 参数 0

候选处理
  迁移来源需要返回值关系
  调用点转换需要适用的解码规则
```

相同根因可关联多条传播路径。独立根因应分别保留。对于同一输入快照、规则和策略，诊断顺序和方案结果应确定，规则注册顺序变化应得到相同结果或相同歧义。

**改写计划应明确每项生成动作及其依据。**

计划应列出方法描述符、实现选择、调用调整、转换插入、局部变量布局、装箱拆箱、字段、数组、容器实现和元数据的实际变化。原方法移除和旧描述符转发方法的生成也应显式列出。

生成过程应处理 long 与引用在槽宽、加载存储、栈操作和帧类型上的差异。方法句柄、invokedynamic、动态常量及其他符号引用，按实现支持能力进行改写或报告相关边界。

验证应覆盖方法与字段解析、调用种类、描述符一致性、访问权限、新签名冲突、相关覆盖关系、栈和局部变量，以及计划要求的调用和存储覆盖。层次信息应通过快照和资源元数据取得，分析与帧计算应避免触发业务类初始化。

输入和计划应持有独立快照，失败后仍可用于诊断和重复分析。所有输出验证成功后，才发布本批次的可用产物。

整批发布约束适用于分析产物和运行时缓存。JVM 中各个类的定义分别发生，运行时应保存定义阶段失败状态，并检查后续相关加载。失败报告应包含实际发生的阶段和受影响范围。

**注解语法、选择策略和分析精度仍需通过实验确定。**

迁移身份与多参数声明的关联、辅助方法注解形式、摘要表达方式和规则版本格式均待定。默认传播策略、边界转换策略、歧义选择以及是否支持实现特化，也需要形成明确 API 契约。

容器对象区分精度、调用上下文范围、递归摘要及搜索能力边界应通过样本确定。实现可在精度和成本之间选择可解释的策略，并将仍需补足的信息反映到诊断中。
